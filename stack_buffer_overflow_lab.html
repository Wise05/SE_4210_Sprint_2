Educational Core Concepts & Defensive Countermeasures

1. Growth vs Write Direction

In x86 architectures, stack frames are allocated downwards towards lower addresses when functions are called. However, array operations like strcpy() write upwards towards higher addresses.

Because local buffers are allocated at lower addresses than saved control pointers, un-bounded string writes overflow into adjacent variables, Saved Frame Pointers (SFP), and Return Addresses (RET).

2. Impact of Corruption
  • Variable Overwrite: Modifies program logic flags (e.g., changing isAdmin = 0 to 1).
  • Control Flow Hijack: Overwriting RET redirects instruction pointer RIP to arbitrary code or hidden functions.
  • Crash / Denial of Service: Overwriting RET with invalid addresses triggers Segmentation Fault (SIGSEGV).
3. Defensive Countermeasures
  • Safe APIs: Replace strcpy with bound-checked strncpy, snprintf, or fgets.
  • Stack Canaries: Compiler places secret guard values before RET. Modified canary aborts execution (-fstack-protector).
  • ASLR & DEP/NX: Randomize memory addresses and mark stack non-executable to prevent shellcode execution.

Stack Buffer Overflow Lab Guide

Welcome to the Interactive Memory Lab!

This application is designed for computer science learners to safely explore how memory is arranged on the execution stack and how unchecked buffer inputs alter application control flow.

How to Use This Lab:

  1. Select a Preset Scenario: Choose from presets at the top to auto-fill payloads representing safe inputs, variable overrides, return address hijacks, and stack canary defenses.
  2. Manual Payload Typing: Type ASCII characters or hex bytes using standard notation (e.g., AAAA\x01 or \xb6\x11\x40\x00).
  3. Run or Step Simulation: Click Run Payload to execute automatically or Step to view character-by-character string copying into stack memory.
  4. Observe Dual Panels: Watch line execution highlights in the C code side-by-side with memory row overwrites in the stack frame.
  5. Toggle Security Protections: Enable Stack Canaries or Safe C functions (strncpy) to observe mitigation mechanics in real time.
Educational Safety Note: This interactive model is a simplified conceptual simulator designed strictly for academic coursework and visualization. No actual binary exploitation, shellcode, or malicious payload execution takes place.
